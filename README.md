# Game PWA — Real-time multiplayer starter

An installable **Progressive Web App** scaffold for a **real-time multiplayer game**, built with:

- **Vite + React 19 + TypeScript** — fast SPA
- **Convex** — real-time database & serverless functions (live subscriptions)
- **Clerk** — authentication
- **Tailwind v4 + shadcn/ui** — styling & components
- **vite-plugin-pwa** — manifest, icons, service worker (installable + offline app shell)

It ships with a working vertical slice — sign in → lobby → create/join a room by code → live player list with presence (online dots) and ready-up — so you can drop your actual game logic on top of a proven auth + real-time + PWA foundation.

---

## Prerequisites

- Node 18+ and **pnpm** (`npm i -g pnpm`)
- A (free) **Convex** account — https://convex.dev
- A (free) **Clerk** account — https://clerk.com

## Setup

Neither backend is wired to your accounts yet. Do this once:

### 1. Install dependencies

```bash
pnpm install
```

### 2. Provision Convex

```bash
pnpm dev:convex
```

This opens a browser to log in / sign up, lets you create a project, and **writes `VITE_CONVEX_URL` into `.env.local`** automatically. It also pushes the functions in `convex/` and keeps watching for changes. **Leave it running** in its own terminal.

### 3. Create a Clerk app

1. In the [Clerk dashboard](https://dashboard.clerk.com), create an application (enable whichever sign-in methods you want — email, Google, etc.).
2. Go to **API Keys** and copy the **Publishable key** (`pk_test_…`).
3. Paste it into `.env.local`:

   ```
   VITE_CLERK_PUBLISHABLE_KEY=pk_test_xxxxxxxx
   ```

### 4. Connect Clerk → Convex (JWT template)

1. In Clerk, open **JWT Templates → New template → Convex**. This creates a template **named `convex`** (don't rename it — `convex/auth.config.ts` expects `applicationID: "convex"`).
2. Copy the template's **Issuer** URL (your Clerk **Frontend API URL**, e.g. `https://your-app.clerk.accounts.dev`).
3. In the [Convex dashboard](https://dashboard.convex.dev) → your project → **Settings → Environment Variables**, add:

   ```
   CLERK_JWT_ISSUER_DOMAIN = https://your-app.clerk.accounts.dev
   ```

   (The `pnpm dev:convex` process picks this up automatically.)

### 5. Run the app

In a **second terminal** (keep `pnpm dev:convex` running in the first):

```bash
pnpm dev
```

Open the printed URL, sign in, and you're in the lobby.

> Tip: `pnpm dev:all` runs Convex and Vite together in one terminal.

## Try the real-time demo

1. Sign in, click **Create**, name a room. You'll get a 4-character code.
2. Open a second browser (or an incognito window / phone), sign in as a different user, and **Join** with that code.
3. Watch both player lists update **instantly**. Toggle **ready** — it syncs live. Online dots reflect the presence heartbeat; close a tab and that player goes "away" within ~10s.
4. When everyone's ready, the **host** can **Start game** — the room flips to `playing`, where your gameplay component mounts (see `src/components/Room.tsx`).

## Project structure

```
convex/                 # Backend (Convex functions + schema)
  schema.ts             # users, rooms, players tables
  auth.config.ts        # Clerk JWT validation
  users.ts              # getOrCreateUser, current, auth helpers
  rooms.ts              # create/join/leave/setReady/startGame + live queries
  presence.ts           # heartbeat mutation
  _generated/           # Codegen (regenerated by `convex dev` — committed)
src/
  main.tsx              # Clerk + Convex providers, router root
  App.tsx               # auth gating + routes (lobby / room)
  components/           # SignInScreen, Lobby, Room, AppHeader,
                        #   OfflineIndicator, InstallPrompt, ui/ (shadcn)
  hooks/                # useStoreUser (mirror Clerk→Convex), useHeartbeat
  index.css            # Tailwind v4 + theme tokens
vite.config.ts          # React, Tailwind, PWA plugin
pwa-assets.config.ts    # icon generation from public/logo.svg
```

## Scripts

| Command | Description |
| --- | --- |
| `pnpm dev` | Run the Vite dev server |
| `pnpm dev:convex` | Run the Convex backend (codegen + push + watch) |
| `pnpm dev:all` | Run both together |
| `pnpm build` | Typecheck + production build (generates the service worker) |

| `pnpm generate-pwa-assets` | Regenerate icons after editing `public/logo.svg` |

## Making it your game

- **Schema:** the `rooms` / `players` tables are intentionally generic. Add game-state tables (or a `gameState` field on `rooms`) in `convex/schema.ts`.
- **Game logic:** add mutations/queries in `convex/` and subscribe with `useQuery` — every connected client updates in real time automatically.
- **Gameplay UI:** replace the `status === "playing"` placeholder in `src/components/Room.tsx`.
- **Presence at scale:** this uses a simple `lastSeen` heartbeat. For typing/cursor presence or large rooms, swap in the official [`@convex-dev/presence`](https://www.convex.dev/components/presence) component.

## Testing the PWA

PWA features (service worker, install) only run in a production build:

```bash
pnpm build && pnpm preview
```

Then in Chrome DevTools → **Application**: check the **Manifest** (installable) and **Service Workers** (active). Run **Lighthouse → PWA**. Toggle **offline** in the Network tab — the app shell still loads and the offline banner appears.
